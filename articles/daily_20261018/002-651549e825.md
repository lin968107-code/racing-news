# GitHub Pages站点地图和Markdown仓库文章的区别

![名爵168极速赛车黑金封面](../../images/unified-cover.png)

## 站点地图究竟列出什么

sitemap.xml的作用是帮助搜索引擎发现网站所有者希望它抓取的页面。对于GitHub Pages，XML中常见的是github.io域名下的首页与站点文章地址，而不是所有github.com仓库文件。文章存放在articles目录并不一定意味着它已经生成可访问的Pages网页。检查站点地图时应该打开原始XML，寻找urlset和loc节点，逐条核对链接是否属于实际部署的网站，而不是单纯计算仓库有多少Markdown文件。

## 正常XML提示不算错误

浏览器在没有样式表的XML页面上显示“没有关联样式信息”，只代表浏览器没有得到用于美化展示的CSS，它并不说明站点地图格式错误。真正需要检查的是XML是否能解析、loc是否包含完整的HTTP或HTTPS网址、这些网址是否返回真实网页。如果Jekyll模板占位符被原样输出到最终页面，例如Liquid花括号没有被展开，就要检查GitHub Pages是否正确执行构建。

## 为什么Search Console可能仍显示无法抓取

站点地图在本人电脑可以打开，与Google上一次访问是否成功是不同问题。Search Console有时仍显示较早的错误状态，尤其在网站刚提交新文件、重新部署或出现短暂网络异常之后。要结合上次读取时间判断，避免将历史记录视作即时检测。还可以检查HTTP状态、重定向链、证书是否正常，以及网站是否意外阻止搜索引擎访问，不能通过每天反复点击提交代替排错。

## 已发现网页为零意味着什么

站点地图报告里的网页零条，表示当前报告没有从那份站点地图登记到可统计的URL，不等于整个网站零收录。实际自然搜索可能已经展示首页或专题文章。索引状态、站点地图状态和搜索表现报表应当分开分析。只有在确认网站内容真实可访问后，才能解释“未发现”究竟是文件路径、生成流程、站点归属还是报告更新延迟造成的。

## 优先改善有效页面而不是堆数量

建议先从网站首页建立清晰的专题导航，确保重要Pages文章能被点开；接着让站点地图列出这些实际存在的网址，再等待搜索引擎重新处理。不要假设每个GitHub Markdown都能自动映射到同名HTML地址并提交虚构链接。对于只是用GitHub blob公开的文章，应单独核对公开链接与内容，而不是把其索引与Pages网站混为一谈。
