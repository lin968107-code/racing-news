## Markdown 图片显示失败的常见原因

GitHub 仓库中的 Markdown 文件可以直接显示图片，但图片链接必须正确指向实际存在的文件。文章上传成功并不表示图片一定能正常显示。检查时应优先确认目录层级、图片名称、扩展名和大小写。

## 一、核对图片路径

在本仓库中，文章统一放在 `articles` 目录，黑金封面放在 `images/unified-cover.png`。因为两个目录都位于仓库根目录，所以文章里可使用 `../images/unified-cover.png`。若把文章误放进 `articles/articles`，原路径就会失效，需要移动文章或调整相对路径。

## 二、检查文件名称

Windows 有时隐藏扩展名，导致重命名时误写成 `.png.png`。GitHub 文件名必须与 Markdown 中引用的名称一致，例如不能把 `统一封面.png` 当成 `unified-cover.png`。大小写不一致也可能造成问题。

## 三、查看 GitHub 图片链接

在 Markdown 页面点击图片文字或图标，观察跳转地址是否指向仓库中的真实图片。还可以单独打开图片文件，确认它已经提交到主分支并且能够正常预览。如果新图片已经上传但页面仍显示旧图，可以强制刷新浏览器。

## 四、批量发布时的检查方法

批量发布文章之前，应先确定统一封面的固定路径。随后抽查开头、中间、结尾各几篇文章，不只检查第一篇。如果所有文章共用同一张图，图片本身上传一次即可，不需要重复提交一百份。修改文章目录时，要同步检查相对路径是否改变。

## 五、需要区分的其他问题

搜索引擎收录状态与图片显示状态是两回事。即使图片显示正常，也不能保证百度马上收录。文章使用的未来日期只是编辑编号计划，不代表真正的上传日期，实际发布时间应以 GitHub 的历史记录为准。
